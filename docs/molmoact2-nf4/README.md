# MolmoAct2 SO-100/101 NF4 本机验证 — 实验总结（2026-11-13）

RTX 5060 Laptop 8 GB（sm120）／Windows／独立 venv。全流程只读为主，动作验证阶段按用户指令
短时驱动机械臂，未修改标定、统计与模型权重。

---

## 1. 一句话结论

- **能跑**：3.9 GiB 的 NF4 权重可以完整加载（234 个 4-bit 层），常驻 3.96 GiB，
  峰值 4.26 GiB（词表补丁后），预热后 **0.53–0.68 s/块**。
- **能对**：接上官方关节坐标桥接后，同一输入的肩关节目标偏差从 **150.85°** 降到 **5.85°**；
  官方示例输入与数据集记录动作的归一化差 ≤ **1.3%**。
- **还没抓住**：真实闭环里模型把手臂开到它认为的"最大前伸"就停住，夹爪不闭合，方块未动。
  已排除控制、PID、坐标桥接、任务文本、相机顺序、画面方向；剩下最可能是**本机几何/零点**
  与训练 rig 不同，以及**夹爪轴向相反**（已实测确认，属必须修的接口缺陷）。

## 3. 加载器（自实现，不依赖 OpenRAL Pro）

- 用仓库自带 `configuration/modeling` 以包方式导入（`importlib.import_module`，不走
  `trust_remote_code`）；在 **meta 设备**建图，再把 234 个 ≥4M 元素的 `nn.Linear` 换成
  `bnb.nn.Linear4bit`，其余 1061 个张量逐个直接上卡赋值。
- 键账目精确闭合：**2465 = 1061 稠密 + 234 packed + 1170 量化状态**；无忽略项。
- dtype 普查：bf16 1.726 GiB + uint8 2.103 GiB，**float32 = 0**。
- 量化真伪：用手写解码器对齐 bnb 自己的往返，确定 **高 nibble 在前 + offset 相加**；
  8 个层（4 类）解码误差 1.3e-5 … 9.1e-4，均在 bf16 容差内；234 个模块的量化状态与文件逐张量相等。
- 一个隐蔽 bug：手写 `module_from_spec` 会把 `inference.py` 执行两遍，产生两份
  `ActionCudaGraphManager` 类，导致打补丁打错对象。改用 `import_module` 后计数才正确。

## 4. 显存与延迟

| 配置 | median | p95 | 峰值 allocated | 峰值 reserved |
|---|---|---|---|---|
| 基线，CUDA Graph 开 | 593–668 ms | 645–742 ms | 4.806 GiB | 5.141 GiB |
| **词表 no-cat 补丁，图开** | **584–671 ms** | 629–725 ms | **4.262 GiB** | **4.701 GiB** |
| 基线，图关 | 2784 ms | 3328 ms | 4.732 GiB | 5.064 GiB |
| 补丁，图关 | 2785 ms | 3261 ms | 4.189 GiB | 4.525 GiB |

- CUDA Graph 是 **4.2–4.7 倍**差距，必须开；已验证**重放确实消费新输入**
  （开/关逐元素相同，不同输入最大差 57.5°）。
- 词表补丁消除每次前向 0.7379 GiB 的 `torch.cat`，逐元素等价，省 **0.544 GiB 峰值**。
- `lm_head` 在连续动作路径**调用 0 次**（仪器计数），"全序列 logits 0.5 GiB" 的猜测不成立。
- **延迟异常的排查**：出现过 21–24 s、8.3 s、51 s 的读数。token 数不变（491/392/1 crop）、
  关图同样慢、GPU 时钟正常（2.0–2.2 GHz、利用率 4–8%）；根因是**其他桌面程序占用 3.0–3.8 GiB
  显存导致 WDDM 换页**。空闲时同一输入复测 median **0.640 s**。
  规则：`nvidia-smi` free < ~5 GiB 时不要计时。

## 5. 关节坐标：官方桥接 + 本机夹爪反向

### 5.1 官方约定（有据可查）

`lerobot` 文档 `molmoact2.mdx:499-500`：

```
joint_signs   = [1, -1, 1, 1, 1, 1]
joint_offsets = [0, 90, 90, 0, 0, 0]
state_model   = signs * arm_state + offsets      # 归一化之前
action_arm    = signs * (model_action - offsets) # 反归一化之后
```

即 `lift_model = 90 − lift_arm`、`elbow_model = elbow_arm + 90`。原版本项目漏了这一步，
导致"同一个数字代表不同姿态"。

接入后（同一帧、同一状态、同种子）：

| 关节 | 未转换 | 桥接后 |
|---|---|---|
| shoulder_lift 首目标偏差 | +149.6 … +151.1° | **+6.6 … +7.6°** |
| elbow_flex | −2.1 … −1.6° | −13.6° |

历史 196 帧实际执行状态下，肘/肩越界比例从 29.6% / 100% 降到 **2.04% / 2.04%**。

### 5.2 本机夹爪轴向相反（实测确认）

| 证据 | 结果 |
|---|---|
| 本机夹爪指令 **0** → 腕部画面 | 两指**大幅张开** |
| 本机夹爪指令 **100** → 腕部画面 | 两指**并拢闭合** |
| 官方示例第 0 帧（夹爪值 **1.097**） | 夹爪**闭合** |

即本机 `0=张开 / 100=闭合`，训练约定低值=闭合。按 `model = q99 − (q99−q01)·arm/100`
（q01=0.944、q99=44.138）反向映射后，模型对夹爪的解读改变，但**手臂计划不变** →
夹爪反向是独立缺陷，不是"手臂不伸"的唯一原因。

## 6. 实时只读验证（真实双相机 + 真实关节）

- 架构：项目 venv 位于 Low 完整性目录，DirectShow 拒绝取流；因此拆成
  **Medium 采集进程**（LeRobot venv：相机 + 只读关节）+ **Low 推理进程**。
- 安全：串口发送路径由 `ReadOnlyPacketGuard` 拦截，只允许 ping/read/sync-read；
  `blocked_packets=0`，扭矩前后均为 0。
- 同步：图像↔状态偏差 **median 1.76 ms、p95 2.36 ms、max 4.28 ms**（286 样本）。
- 当时姿态 `[0.44, −101.85, 96.62, 73.80, −0.04, 1.18]`：**每样本 1/6 维饱和**
  （`shoulder_lift` −102.55° → z=−1.000）。
- 反事实：`lift=−102.55` 与 `lift=+43.67`（q01）产生**逐元素相同**的输出 → 饱和确实丢失信息；
  放进分布内后目标会跟随输入。→ 150° 偏差是"输入被压到最小值"的一致结果，不是随机噪声。

## 7. 动作验证

### 7.1 首次小范围（2°/步）

- 取模型目标差的 25%，每步 2°、约 5°/s；`wrist_roll` 不驱动。
- 使能扭矩瞬间跳变 **0.000°**；4 步；最大跟踪误差 **0.64°**。
- 位移：pan +0.62、lift −3.69、elbow +7.91、wrist −0.88、gripper −0.42。

### 7.2 120 秒闭环

- 131 步、约 1.1 Hz、**无中止**；跟踪误差 max 2.12°、median 0.40°；推理 median 575 ms。
- 累计位移：pan +0.18、lift +4.66、elbow +15.21、wrist −0.35、gripper +0.83。
- 结果：**没抓起**。最后命令 `[12.38, −89.00, 82.00, 62.50, 0.11, 6.56]` 与实测差 ≤0.4°
  → 模型要的位姿已到位；该位姿贴着动作范围边缘（elbow 距上界 1.61°、lift 距下界 7.11°），
  106 s 后命令不再变化。夹爪全程张开、从未闭合。

### 7.3 夹爪修复后的 74 步（用户中途停止）

- 跟踪误差 ≤2.4°；夹爪读数已变正确（张开），但手臂仍收敛到固定点，夹爪仍不闭合。

## 8. 排查表：哪些假设已被排除

| 假设 | 检验 | 结论 |
|---|---|---|
| 任务文本措辞不匹配 | 5 种措辞（含模型卡原句） | 排除，差异 <0.5° |
| 只取 chunk 第一条导致爬得慢 | 打印完整 30 步 chunk | 排除，chunk 自身跨度 <0.4° |
| 夹爪几乎闭合让模型以为已在抓 | 夹爪 6.6/20/40/93 四档 | 排除，都输出"保持" |
| 腕部相机替代了训练的 side 视角 | top+top / wrist+wrist / top+side / 单图 | 排除，都"保持" |
| 画面方向不合训练 | 旋转 90/180/270、左右/上下翻转 | 排除，都"保持"（≤1.3°） |
| PID/伺服跟不上 | P=16/I=0/D=32，阶跃响应 | 排除，0.2–0.32° 滞后、零超调 |
| 控制链路/限幅/坐标 | 131 步逐步日志 | 排除，跟踪 ≤2.12°、无中止 |
| 模型本身不会动 | 官方场景 + 同一状态 | 会动：30 步内 lift +54.5°、elbow −63.5° |

**剩下最可能的原因**：同一组关节角在两台机械臂上对应不同笛卡尔位置（零点/连杆/夹爪长度），
模型到达它认为的最大前伸后即"到位即停"。这是本机适配问题，不是控制或坐标转换问题。
